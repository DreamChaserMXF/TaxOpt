# 微信小程序开发总计划

## 1. 开发目标

### 1.1 总目标

开发一个微信小程序版本的 TaxOpt，整体能力尽量对齐现有网页版，覆盖以下核心场景：

- 税筹优化：输入全年名义收入，自动优化月薪/年终奖拆分
- 收入计算：输入月薪、年终奖，直接计算税后结果
- 额外收入处理：支持额外激励、股票激励
- 城市预设与自定义参数：支持加载预设、展开并修改社保公积金参数
- 专项附加扣除：支持全部已有扣除项
- 结果分析：支持结果横幅、指标卡片、收入/税额构成、年终奖明细、月度明细、图表
- 历史记录：支持保存、恢复、删除历史计算记录

### 1.2 对齐网页版的目标范围

计划以“网页版几乎所有功能”为目标，建议分成两层：

#### 第一层：必须对齐

- `optimize` / `calc` 两种模式
- 优化目标切换
- 全部输入项
- 全部核心结果字段
- 历史记录
- 年终奖明细
- 月度明细
- 图表
- 股票激励相关展示
- 预设加载与自定义参数编辑

#### 第二层：允许小程序化替代

- 网页的 `导出 PDF`
  小程序不建议照搬浏览器打印能力，改为“保存长图”或“生成分享卡片”
- 网页的 `导出 Excel`
  当前小程序可不支持；如后续确有需要，再单独评估服务端导出或本地生成
- 网页的大表格横向展示
  小程序需要做移动端压缩布局、分组卡片或横向滚动优化

### 1.3 建议验收标准

验收时至少满足：

- 与网页版输入同一组参数，关键结果字段一致
- 小程序可完整走通“输入 -> 计算 -> 查看结果 -> 返回修改 -> 查看历史 -> 恢复结果”
- 小程序支持额外激励、股票激励
- 小程序支持城市预设和参数手改
- 小程序结果页在主流机型上可正常滚动和阅读

## 2. 页面规划

建议小程序从当前的 2 页骨架升级为 4 个页面/功能单元，其中 3 个是正式页面，1 个可先做弹层后续再独立成页。

### 2.1 页面一：计算首页

路径建议：`pages/index/index`

功能：

- 选择计算模式：税筹优化 / 收入计算
- 输入收入参数
  - 税筹优化：全年名义收入、优化目标
  - 收入计算：月薪、年终奖
- 输入其他收入
  - 额外激励
  - 股票激励（多笔）
- 选择城市预设
- 展开并编辑社保、公积金参数
- 输入专项附加扣除
- 表单校验
- 发起计算
- 展示最近历史记录入口

说明：

- 当前小程序首页还未覆盖“其他收入”输入，需要补齐
- 当前首页已有模式、预设、参数、专项扣除、历史记录骨架，可以复用

### 2.2 页面二：计算结果页

路径建议：`pages/result/result`

功能：

- 顶部方案横幅
  - 方案标题
  - 全年名义收入
  - 月薪/年终奖拆分
  - 额外激励摘要
  - 股票激励摘要
- 指标卡片区
  - 名义收入
  - 到手现金
  - 公积金入账
  - 现金+公积金
  - 全年个税
  - 税率
  - 个人社保
  - 广义税率
- 收入与税额构成区
  - 工资薪金
  - 额外激励说明
  - 年终奖
  - 股票激励逐笔
  - 合计行
- 年终奖明细区
- 股票明细区
- 图表区
  - 年度收入构成
  - 月度到手趋势
- 月度明细区
- 返回修改
- 导出/分享操作

说明：

- 当前结果页仅覆盖“提示 + 指标卡片 + 年终奖明细 + 月度明细”
- 与网页版相比，缺少结果横幅、收入税额构成、股票明细、图表落地、导出能力

### 2.3 页面三：历史记录页

路径建议：`pages/history/index`

功能：

- 以列表形式展示历史记录
- 按模式/时间查看历史项
- 删除单条历史
- 清空历史
- 点击进入结果详情

说明：

- 当前小程序历史记录嵌在首页底部，短期可保留
- 若历史记录量增大，建议独立页面，首页只保留最近 3~5 条和“查看全部”入口

### 2.4 页面四：导出/分享页或弹层

实现方式建议先做弹层，再视复杂度决定是否独立页面

功能：

- 保存结果长图
- 复制主要结果摘要
- 生成分享卡片

说明：

- 这个能力是网页版“导出 PDF”的小程序化替代方案；Excel 导出暂不作为小程序必需能力
- 若时间紧，可放到第二阶段

## 3. 页面跳转关系

建议跳转关系如下：

1. 首页 `pages/index/index`
   - 点击“开始计算” -> 本地计算 -> 跳转结果页 `pages/result/result`
   - 点击“历史记录某一项” -> 直接跳转结果页 `pages/result/result`
   - 点击“查看全部历史” -> 跳转历史页 `pages/history/index`

2. 历史页 `pages/history/index`
   - 点击某条记录 -> 跳转结果页 `pages/result/result`
   - 点击“重新编辑” -> 回首页并回填参数

3. 结果页 `pages/result/result`
   - 点击“返回修改” -> 返回首页
   - 点击“导出/分享” -> 打开导出弹层或跳转导出页

4. 导出弹层/导出页
   - 保存长图 / 分享后关闭，回到结果页

可以抽象为：

`首页 -> 结果页`

`首页 -> 历史页 -> 结果页`

`结果页 -> 首页`

`结果页 -> 导出弹层(或导出页) -> 结果页`

## 5. 开发步骤

建议按 6 个阶段推进。

### 阶段一：补齐输入能力

目标：

- 让首页输入能力与网页版对齐

任务：

- 在小程序首页加入“额外激励 / 股票激励”输入区
- 支持多笔股票激励的增删改
- 接口请求带上 `extra_income` / `stock_grants`
- 修正历史记录保存与恢复逻辑，确保这些字段被保存和回填
- 增加输入校验和错误提示

产出：

- 首页输入项与网页版基本一致

### 阶段二：补齐结果页结构

目标：

- 让结果页具备网页版的主要信息结构

任务：

- 增加顶部方案横幅
- 增加名义收入与拆分展示
- 增加额外激励/股票激励摘要
- 增加股票明细区
- 增加收入与税额构成区

产出：

- 结果页核心信息结构完整

### 阶段三：补齐图表能力

目标：

- 落地图表，增强分析体验

任务：

- 引入 `qiun-data-charts` 或同类小程序图表组件
- 实现年度收入构成图
- 实现月度到手趋势图
- 调整移动端图表尺寸与图例布局

产出：

- 小程序结果页图表可用

### 阶段四：优化历史记录与导航

目标：

- 让使用路径更顺手

任务：

- 评估历史记录是否从首页抽离为独立页面
- 增加“查看全部历史”入口
- 统一结果缓存与参数回填机制
- 完善“返回修改”和“重新编辑”体验

产出：

### 阶段五：补齐导出与分享

目标：

- 为小程序提供网页版导出能力的可替代方案

任务：

- 评估保存长图方案
- 评估结果分享卡片方案

产出：

### 阶段六：联调、测试与发布准备

目标：

- 确保上线前稳定可用

任务：

- 与 Python 核心计算做一致性测试
- 测试参数边界、离线场景、空结果、长列表
- 真机测试不同屏幕尺寸
- 如启用远程能力，再配置合法域名
- 完成微信开发者工具与提审准备

产出：

- 可提测版本

## 6. 风险与备注

### 6.1 平台能力差异风险

- 小程序没有浏览器打印能力，`导出 PDF` 无法直接照搬
- 小程序 Excel 导出暂不作为必需能力

建议：

- 用“保存长图 / 分享卡片”替代“打印 PDF”

### 6.2 图表落地风险

- 网页版使用 Chart.js
- 小程序端不能直接复用，需要换成小程序图表组件
- 图表库在不同机型上的性能和兼容性需要验证

建议：

- 优先选成熟的小程序图表组件，并先落地两个最关键图表

### 6.3 表单复杂度风险

- 小程序输入项多、层级深，长页面会降低填写效率
- 股票激励多笔输入在移动端操作成本高

建议：

- 做分组折叠
- 控制默认展开项
- 强化滚动定位和错误提示

### 6.4 结果页过长风险

- 结果页包含横幅、卡片、构成表、图表、月度明细，可能过长

建议：

- 用“分组卡片 + 折叠区块 + 横向滚动表格”优化
- 先保证关键信息首屏可读

### 6.5 计算逻辑双端维护风险

- Python 核心仍是 CLI/API 真相源
- 小程序端维护等价 JS 实现，后续改税法或算法时需要同步

建议：

- 保留 Python 与小程序 JS 的一致性测试
- 调整 `main.py` 后同步更新 `miniprogram/utils/tax-core.js`

### 6.6 数据一致性风险

- 当前网页版与小程序在结果展示字段上并未完全一致
- 若历史记录、缓存、结果字段口径不统一，容易出现展示错误

建议：

- 统一以 `main.py` 结果字段为唯一真相源
- 为关键结果字段补充对照清单

### 6.7 开发节奏风险

- 如果一开始就追求 100% 视觉对齐，会拖慢交付

建议：

- 先做“功能对齐”
- 再做“视觉和交互精修”

## 7. 建议的实施顺序

建议按下面顺序执行，风险最低：

1. 先补输入功能
2. 再补结果结构
3. 再补图表
4. 再整理历史记录
5. 最后做导出/分享

### 8.1 当前已具备

- 首页与结果页骨架
- 两种模式切换
- 预设读取
- 自定义参数编辑
- 专项扣除输入
- 基础历史记录
- 基础结果卡片
- 年终奖明细
- 月度明细

### 8.2 当前明显缺失

- 额外激励输入
- 股票激励输入
- 结果横幅完整信息
- 收入与税额构成表
- 股票明细
- 图表正式落地
- 导出/分享
- 更适合移动端的历史记录组织方式

## 9. 结论

这个小程序不是从零开始，而是“已有骨架、需要补齐能力”的项目。

最合理的推进方式不是一次性大改，而是：

- 先把输入和结果能力补平
- 再做图表和历史记录重构
- 最后做导出/分享与发布准备

按照这个计划推进，可以较稳地做出一个和网页版能力高度接近、但更适合小程序使用场景的版本。
